# AGENTS.md

Vue 3 + Vite + TS admin console, embedded into the inkwash-server binary via rust-embed and always served same-origin. No router, no state library: `App.vue` holds a `view` ref and coordinates everything; child views `inject(uiKey)`.

## Where to look

- `src/App.vue` (310L) — coordinator. Owns `session` ref + restore (`onMounted` → `api.me`, :229-243), `view` ref (`"dashboard"|"device"|"account"`, :24), device list + per-device stats, global toast/confirm/prompt modals, `busy` ref. Provides the whole UI service object via `provide(uiKey)` (:213-227); `handle()` (:105) and `run()` (:117) are defined here, not in lib.
- `src/LoginView.vue` (170L) — account login/register + admin-token fallback (`submitAdmin`, :51-66). Only file that calls api outside `ui.run` (pre-session; local `busy` + inline errors, :36-46, :58-65).
- `src/DashboardView.vue` (143L) — stat strip + device cards + register device; reads `devices`/`stats` from props.
- `src/DeviceView.vue` (523L) — full alarms/todos/channels/inbox editor for one device; loads its own content, receives only `device` prop. `loadContent` (:40) with seq guard (:38); every mutation goes `ui.run(...)` then `await loadContent()` (:69, :94, :110, :124, :133, :166, …); `onMounted(loadContent)` + `watch(() => props.device.id, loadContent)` (:329-330).
- `src/AccountView.vue` (175L) — session info, change password, sign out.
- `src/lib/api.ts` (205L) — single `request<T>` fetch wrapper (:17-42) returning `Result<T>` (`{ok,value}|{ok:false,status,error}`); one typed fn per endpoint; all paths relative, bearer token passed in. 401 surfaces as `Result` — handling lives in App.vue.
- `src/lib/ui.ts` (22L) — `UI` interface + `uiKey: InjectionKey<UI>`; the only channel for views to reach shared services.
- `src/lib/storage.ts` (35L) — localStorage keys `inkwash.admin.session` / `inkwash.admin.token`; `Session {kind:"account"|"admin", token, username}`; JSON-parse guard removes corrupt entries on load (:31-34).
- `src/lib/clipboard.ts` (31L) — `copyText`: `navigator.clipboard` when `window.isSecureContext`, else `execCommand('copy')` fallback (console is usually opened over plain LAN http). Callers must run inside a user-gesture handler for the fallback to work.
- `src/lib/types.ts` (90L) — two-tier: re-exports of `generated/` (server-local DTOs) + handwritten mirrors of the git-pinned `inkwash-logic` types (`Repeat`, `Alarm`, `Todo`, `InboxItem`, `Upsert*Input`). Handwritten copies must stay in sync with `../inkwash/logic/src`; generated ones with `../src/models.rs`.
- `src/lib/generated/*.ts` (AccountSummary, Channel, ChannelCreated, Device) — ts-rs output, regenerated by `cargo test`; never hand-edit, commit together with the model change.
- `src/main.ts`, `src/env.d.ts`, `tsconfig.json` — stock scaffold; nothing custom.
- `vite.config.ts` — dev server :5173, proxies `/api` + `/health` → `127.0.0.1:8080`; `build.outDir: "dist"` (what rust-embed embeds).

## Conventions

- After any successful mutation, re-fetch (`loadContent()` in DeviceView, `loadDevices()` in App.vue) instead of patching local refs.
- All reads that can race use a seq guard: `let loadSeq` + `const seq = ++loadSeq` + `seq !== loadSeq` check (App.vue:134-137, DeviceView.vue:38-42) — stale responses are dropped, never merged.
- New endpoint → typed fn in `api.ts` + wire type in `types.ts`, then verify the path against `src/routes.rs`.
- Views read `ui.toast`/`ui.confirmDialog`/`ui.promptDialog`; never reimplement modals or error toasts locally.

## Anti-patterns

- Hardcoding a base URL / absolute origin in `api.ts` — fetch uses relative paths only (api.ts:24); the console is same-origin with the API by design (embedded build + LAN http), a configurable base breaks both.
- Handling 401 outside `ui.run`/`handle` — shared session drop is `onUnauthorized` (App.vue:90-95) reached from `handle` (:108-110); ad-hoc error handling elsewhere leaves a dead session in localStorage and the app stuck post-logout.

## Commands

- `npm run dev` — vite :5173 (proxies to a separately running `cargo run` on :8080).
- `npm run codegen` — after breaking DTO edits: sets `INKWASH_SKIP_UI_BUILD=1` and runs `cargo test --quiet export_bindings` from the server root (`cd ..`), so the vue-tsc build pass is skipped against stale bindings.
- `npm run build` — `vue-tsc --noEmit && vite build` → `dist/`; also run by the server's build.rs on every cargo build (panics without `node_modules`).

## Notes

- No tests in this package; the type-check (`vue-tsc`) is the only static gate, and the server's `cargo test` regenerates bindings that must still compile against it.
